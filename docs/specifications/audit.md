# Documentation audit

**Source baseline:** `c5e1f5c613fa02ffa507db333e4702da6c97e488`.
**Inspected:** 2026-10-09.
**Branch scope:** Main-derived repository implementation; not published-package or release-branch certification.

This audit records the relationship between existing documentation and the current implementation. It separates historical designs from current behavior and makes the depth of each check explicit. Use the [specification guide](README.md) for reconciliation rules and the [architecture index](../architecture/README.md) to navigate the product baselines.

The feature/design inventory contains **38 existing Markdown documents and two associated JSON schemas**. All have a scoped disposition below; none is declared exhaustively conformant. The new baselines provide **24 MSTest contracts and 17 MTP contracts**. Supporting guides and release history are inventoried separately.

## Dispositions and assurance

| Disposition | Meaning |
| --- | --- |
| Consistent at topic level | The named behavior was traced to implementation and relevant existing tests without identifying a discrepancy in that scope. Other clauses are not implicitly verified. |
| Complemented | A current implementation note or correction was added for a verified difference. The original design/history remains. |
| Historical partial | Some of the proposal maps to current code, but its complete proposed contract is not established. |
| Historical unimplemented | The proposed contract is not the current implemented approach, based on the identified implementation or explicit decision note. |
| Not fully audited | Inventory or limited inspection only; no claim of clause-level conformance. |

Source inspection and test mapping do not mean tests were executed. A linked test demonstrates only the behavior it asserts, not every statement in the document. Historical proposal disposition is not a newly inferred acceptance or rejection decision.

## Inventory boundary

Feature/design audits cover the RFCs and feature, protocol, graph-query, source-generator, and schema documentation under `docs/`, plus the HangDump and VideoRecorder design documents under `src/Platform/`. They do not certify all package readmes, samples, generated API documentation, workflow instructions, release notes, or external Microsoft Learn pages.

For linked schemas, the audit concerns the inspected schema and implementation paths, not a declaration that every valid or invalid JSON instance was executed against every host mode. For protocols, local serializers and handlers do not establish conformance of an external IDE or .NET SDK consumer.

## Remaining detailed-contract coverage

The product baselines list exclusions per contract. Important areas still without exhaustive current specifications include assertion overload/source compatibility and diff/formatting semantics; discovery identity/serialization; data-row metadata precedence; lifecycle failure/cancellation and context flow; UI/STA/deployment/loading matrices; retry/hot-reload behavior; report schemas/recovery/attachments; telemetry/privacy/resource identity; AI networking; generated metadata completeness and AOT/trim preservation; complete CLI/configuration/wire catalogs; and SDK/profile/extension composition.

External SDK/IDE/collector behavior, real multi-module aggregation, no-handshake/legacy/partial/cancellation combinations, release-branch behavior, and servicing/backport needs require shipping-layout validation with aligned components. Topic-level source comparisons and fake-peer fixtures do not close those gaps.
